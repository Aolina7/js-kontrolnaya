## Часть A. Почему так

### A1 — почему изменилось и у `a`
Т.к. a изначально является объектом, т.е. это ссылочный тип данных, а ссылочные типы данных копирую не сам объект, а ссылку на его расположение в памяти.


### A2 — почему `3` раньше `2`
В стек вызовов закидываются console.log("1"), console.log("4") и сразу выполняются выводы 1, затем 4, т.к. это синхронные задачи. Далее выполнится promise. setTimeout() это макрозадача, которая при инициализации попадёт в очередь задач, а затем после истечения времени, указанного в аргументах, задача попадёт в стек вызовов, но выполнится только в том, случае если event loop не будет занят.


### A3 — почему счётчик остался нулём
У стрелочной функции нет своего this, она обращается к this родительской функции. Но т.к. родительской функции тоже нет, то this является окно браузера. Соответсвенно у окна браузера нет атрибута n, ничего добавить не получится и при вызове console.log(counter.n) n остаётся исходным.

## Часть B. Что было не так

Четыре находки. По каждой: в чём была проблема и что вы исправили.

### Ошибка 1

**Было не так: tasks.filter((task) => task.priority >= 5);**

**Исправил: tasks = tasks.filter((task) => task.priority >= 5);
filter - это не мутирующий метод, т.е. сохраняет исходный массив и возвращает новый, поэтому его нужно пересохранить.**

### Ошибка 2

**Было не так: let countActions = createCounter(); внутри функции**

**Исправил:const countActions = createCounter();
Каждый раз при вызове клика счётчик создавался заново и предыдущие значения стирались. Счётчик нужно инициализировать до функции. Тогда каждый раз при вызове клика обращаемся к уже созданной переменной**

### Ошибка 3

**Было не так: tasks.sort();**

**Исправил: tasks.sort((a, b) => a.priority - b.priority);
Необходимо передать компаратор, в котором указано по какому принципу мы сортируем элементы. Т.к. необходимо сортировать по важности, то нужно сравнивать по атрибуту priority каждого объекта**

### Ошибка 4

**Было не так: const task = tasks.find((t) => t.id === id);**

**Исправил: const task = tasks.find((t) => t.id === Number(id));
item.dataset.id возвращает id как string, а атрибут объекта t.id является числом. t.id === id проверяет строго, т.е. также сравнивает типы данных. Необходимо обернуть id в тип Number.**

### C2 — какой вариант вывода списка и почему

**Выбираю: users.forEach((u) => {
  const li = document.createElement("li");
  li.textContent = u.name;
  list.append(li);
});**

**Причины: 1. Данный вариант более читаемый, разбит на последовательность выполняемых методов.
           2. innerHtml полностью пересоздаёт содержимое, а list мог содержать другие элементы, обработчики, которые сотрутся. append просто добавит новые элементы, не трогая существующие.**
